# QA 체크리스트

자동화 없이 손으로 확인하되, **재현 가능하게** 씁니다.

## 🔑 실패는 볼트에 남깁니다

원본은 결과를 출력만 했습니다. **실패가 기록되지 않으면 같은 곳에서 또 막힙니다.**

```bash
devtrail path trouble    # 실패 케이스를 여기 남긴다
```

Pass 는 화면 출력으로 충분합니다. **Fail 만 노트로 만듭니다.**

## 시나리오 구조

각 항목을 이렇게 씁니다.

```
### <시나리오 이름>
- 사전 조건:
- 단계:
    1.
    2.
- 기대 결과:
- 실제 결과:
- 판정: ✅ Pass / ❌ Fail
```

**단계는 남이 그대로 따라할 수 있어야 합니다.** "로그인한다"가 아니라
"로그인 페이지에서 test@example.com / 비밀번호로 로그인한다" 입니다.

## 실패 처리

Fail 이 나오면 트러블슈팅 노트를 만듭니다. 템플릿은
`$(devtrail path templates)/트러블슈팅 템플릿.md` 를 따릅니다.

| 심각도 | 기준 |
|---|---|
| Critical | 데이터 손실 · 보안 · 전체 중단 |
| High | 핵심 기능이 안 됨 |
| Medium | 우회 가능한 결함 |
| Low | 표기 · 사소한 불편 |

**Critical 과 High 는 원인 가설까지 씁니다.** 증상만 적으면 나중에 다시 조사해야 합니다.

## 하지 말 것

- 확인하지 않은 것을 Pass 로 적기 — 안 했으면 「미실행」이라고 씁니다
- 자동으로 고치기 — QA 는 관찰이고, 수정은 별도 작업입니다
- 심각도 부풀리기

## 결과 보고

```
시나리오 8개 · ✅ 6 · ❌ 2 · ⏭ 미실행 0

❌ High   로그인 후 리다이렉트 안 됨 → 트러블슈팅/2026-08-20 로그인 리다이렉트.md
❌ Low    버튼 라벨 오타
```
