# 학습 기록

## 🔑 경로

```bash
devtrail path study
```

`learn` 모듈이 설치돼 있어야 합니다. 없으면 `devtrail augment learn --apply` 를 안내하세요.

## 무엇을 하나

| 대상 | 하는 일 |
|---|---|
| `dayNN/` | 오늘치 학습 노트를 만들거나 이어씀 |
| `PROGRESS.md` | 일일 기록 한 줄 추가 · 구간 상태 갱신 |
| `WEEKLY-REVIEW.md` | 주말이면 주간 회고 블록 추가 |

## 핵심 — 「막힌 것」을 반드시 채웁니다

```
- 무엇: day12 제네릭
- 이해도: 🟡
- 막힌 것: 조건부 타입에서 infer 가 언제 필요한지 모르겠음
- 오늘의 한 줄: 제네릭은 '타입의 함수'다
```

**이해도만 적고 막힌 것을 비우면 이 기록은 쓸모가 없습니다.**
같은 곳에서 또 막히고, 왜 막혔는지 기억이 안 납니다.

이해도 표기: `✅ 혼자 됨` / `🟡 힌트 필요` / `🔴 다시 봐야 함`

## 절차

### 1. 일차 판별

```bash
ls "$(devtrail path study)" | grep -E '^day[0-9]+$' | sort -V | tail -1
```

마지막 일차 + 1 을 기본으로 제안합니다. 사용자가 다른 걸 지정하면 따릅니다.

### 2. 학습 노트

`dayNN/` 폴더를 만들고 `_day-템플릿.md` 형식으로 씁니다.
**대화 맥락에서 실제로 배운 것만** 씁니다. 커리큘럼을 지어내지 마세요.

### 3. PROGRESS 갱신

일일 기록 블록을 **위에** 추가합니다. 기존 기록을 지우지 않습니다.
구간 진도표의 상태(`⬜`/`🟡`/`✅`)도 함께 갱신합니다.

### 4. 공백 확인

마지막 기록이 3일 이상 전이면 알려줍니다.

> **다그치지 마세요.** "3일 쉬셨네요, 다시 시작해봅시다" 정도면 됩니다.
> 완벽하게 매일 하는 것보다 끊겼을 때 돌아오는 게 중요합니다.

### 5. 주말이면

WEEKLY-REVIEW 에 이번 주 블록을 추가합니다.
🔴 로 표시된 것을 모아 「다시 봐야 할 것」에 넣습니다.

## 하지 말 것

- 「막힌 것」을 비우기
- 안 배운 것을 기록 — 대화에 근거가 있어야 합니다
- 기존 기록 덮어쓰기 — 항상 추가입니다
- 진도를 재촉하기
