# Inbox → 카드노트 승격

**이 스킬이 없으면 제텔카스텐은 멈춥니다.**
원본 볼트에서 Inbox 7개, 카드노트 12개로 멈춰 있던 이유가 이 마찰입니다.

## 🔑 경로

```bash
devtrail path inbox      # 승격 대상
devtrail path zettel     # 승격 목적지
devtrail path moc        # 주제 허브
```

## 승격 조건 — 셋 다 되어야 합니다

| # | 조건 | 왜 |
|---|---|---|
| 1 | **내 언어로 재작성** | 복사해둔 건 이해한 게 아니다 |
| 2 | **`#주제/` 태그** | 나중에 MOC 로 묶인다 |
| 3 | **관련 노트 2개 이상 링크** | 연결 없는 노트는 다시 안 읽는다 |

**하나라도 안 되면 승격하지 않습니다.** 게이트가 없으면 카드노트가
Inbox 의 복사본이 되고, 그 순간 이 시스템은 쓰레기통이 됩니다.

## 절차

### 1. 대상 고르기

```bash
ls -t "$(devtrail path inbox)"
```

오래 묵은 것부터 봅니다. `_index.md` 는 제외합니다.
사용자가 특정 노트를 지정하지 않으면 **가장 오래된 3개**를 제안하고 고르게 합니다.

### 2. 판정

노트를 읽고 셋 중 어디에 해당하는지 판정합니다.

| 판정 | 조건 | 처리 |
|---|---|---|
| **승격** | 3개 조건을 채울 수 있다 | 아래 3단계 |
| **보류** | 내용은 있는데 연결할 노트가 없다 | `review_at` 을 2주 뒤로 미룬다 |
| **폐기** | 다시 안 볼 것이다 | 사용자 확인 후 삭제 |

**폐기는 반드시 확인을 받습니다.** 남의 노트를 임의로 지우지 마세요.

### 3. 승격 작성

- 원본을 **인용하지 말고** 자기 문장으로 다시 씁니다
- `#주제/<슬러그>` 를 붙입니다 — 기존 주제와 겹치는지 먼저 확인
- 관련 노트를 2개 이상 찾아 링크합니다

```bash
# 기존 주제 확인 — 새 주제를 남발하면 MOC 가 파편화된다
grep -rho '#주제/[^ ]*' "$(devtrail path zettel)" | sort | uniq -c | sort -rn
```

### 4. 저장

`$(devtrail path zettel)/YYYYMMDDHHmm 제목.md` 로 만듭니다.
템플릿은 `영구 카드노트 템플릿.md` 를 따릅니다.

frontmatter:
```yaml
type: zettel
status: seedling        # 승격 직후는 seedling
promoted_at: YYYY-MM-DD
source: <원본 노트 경로>
review_at: <30일 뒤>
```

### 5. 원본 처리

원본 Inbox 노트는 **지우지 않습니다.** frontmatter 에 표시만 합니다.

```yaml
status: promoted
promoted_to: <새 카드노트 경로>
```

### 6. MOC 연결

`#주제/` 가 같은 MOC 가 있으면 그 MOC 의 목록에 링크를 추가합니다.
없으면 만들자고 제안만 하고, 만들지는 않습니다.

## 결과 보고

```
승격 N개 · 보류 N개 · 폐기 제안 N개

✅ <제목> → 카드노트  (#주제/xxx · 링크 2개)
⏸ <제목> → 2주 뒤 재방문  (연결할 노트를 못 찾음)
🗑 <제목> → 폐기 제안  (사유)
```

## 하지 말 것

- 3개 조건을 안 채우고 승격
- 원본을 임의로 삭제
- 새 `#주제/` 남발 — 기존 주제를 먼저 확인
- 원문 복사 붙여넣기
