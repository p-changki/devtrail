# 🔌 늘려 쓰기

## 새 프로젝트 추가

`⌘⇧P` 를 누르면 폴더와 docs 골격이 생깁니다.

```
프로젝트/<이름>/
├── README.md          프로젝트 홈
├── docs/
│   ├── 00-overview    01-product    02-domain     03-architecture
│   └── 04-data        05-infra      06-compliance 07-delivery
└── worklogs/          작업 하나 = 폴더 하나
```

번호는 **읽는 순서**입니다. 무슨 문서를 써야 할지 고민하지 않게 하는 것이 목적입니다.

## PR 요약을 받으려면

개발일지의 `#### <레포명>` 섹션 아래에 들어갑니다.
`⌘⇧D` 로 일지를 만들 때 프로젝트를 고르면 섹션이 자동으로 생깁니다.

**섹션이 없으면 요약은 에러 없이 건너뜁니다.** 조용히 아무 일도 안 일어납니다.

프로젝트 목록을 바꾸려면:

```bash
devtrail init          # 다시 돌려서 고르기
```

## 레포 문서 가져오기

각 레포의 `docs/` 를 볼트로 단방향 동기화합니다.

```bash
devtrail sync
```

**볼트에서 고친 내용은 레포로 돌아가지 않습니다.** 거울 폴더이므로 여기서 직접 편집하지 마세요.

## 자동 실행

```bash
devtrail install-schedule    # 매일 정해진 시각에 실행
devtrail doctor              # 돌고 있는지 확인
```

## 모듈 더 설치하기

```bash
devtrail augment --list              # 목록
devtrail augment pkm --apply         # 자료실·카드노트·MOC 추가
devtrail augment learn --apply       # 학습 시스템 추가
```

## 폴더 이름을 바꾸고 싶다면

설정의 `dirs` 를 고치면 됩니다. **템플릿과 쿼리가 따라옵니다** —
경로가 어디에도 박혀 있지 않습니다.

```bash
devtrail path                        # 현재 경로 확인
devtrail augment --apply             # 경로 맵 갱신
```

## 상태 점검

```bash
devtrail scan      # 볼트 구조·메타데이터·충돌 진단 (쓰기 없음)
devtrail doctor    # 의존성·인증·자동화 상태
```
