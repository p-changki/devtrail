# 🔌 Extending

## Add a project

Press `⌘⇧P` and you get the folder plus a docs skeleton.

```
Projects/<name>/
├── README.md          project home
├── docs/
│   ├── 00-overview    01-product    02-domain     03-architecture
│   └── 04-data        05-infra      06-compliance 07-delivery
└── worklogs/          one task = one folder
```

The numbers are **a reading order**. The point is that you never wonder which
document to write next.

## Getting PR summaries

They go under the `#### <repo>` sections in your devlog.
Picking projects when you create the devlog with `⌘⇧D` creates those sections.

**With no section, the summary is skipped without an error.** Nothing happens,
quietly.

To change the project list:

```bash
devtrail init          # run it again and pick
```

## Pull in repo docs

One-way sync of each repo's `docs/` into the vault.

```bash
devtrail sync
```

**Edits in the vault do not go back to the repo.** It is a mirror — do not
edit it here.

## Run it automatically

```bash
devtrail install-schedule    # run daily at a set time
devtrail doctor              # check that it is running
```

## Install more modules

```bash
devtrail augment --list              # what is available
devtrail augment pkm --apply         # Library · zettels · MOC
devtrail augment learn --apply       # learning system
```

## Renaming folders

Edit `dirs` in the config. **Templates and queries follow** — no path is
hardcoded anywhere.

```bash
devtrail path                        # see current paths
devtrail augment --apply             # refresh the path map
```

## Checking state

```bash
devtrail scan      # vault structure · metadata · conflicts (read-only)
devtrail doctor    # dependencies · auth · automation
```
