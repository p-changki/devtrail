# 🗂 Folders and tags

## Tags decide folders

Tag a note `#type/idea` and it **moves itself to the Ideas folder**.
Templates add the tag for you, so usually you never think about it.

## Five namespaces

| Namespace | Meaning | Example |
|---|---|---|
| `#type/*` | Note type **(required)** | `type/devlog` · `type/dev-note/frontend` |
| `#project/*` | Belongs to a project | `project/my-app` |
| `#topic/*` | Subject (recommended) | `topic/rag` · `topic/nextjs` |
| `#maturity/*` | Ripeness (zettels only) | `maturity/seedling` → `budding` → `evergreen` |
| `#area/*` | Area | `area/dev` · `area/resource` |

> `#type/*`, `#project/*`, and `#area/*` are the same in every language —
> the auto-filing rules run on them. Only `#topic/` and `#maturity/` differ
> (they are `#주제/` and `#상태/` in Korean vaults).

## Three stages of ripeness

Zettels only. **Promote everything and you get a bin, not a Zettelkasten.**

```
seedling   just copied down
budding    rewritten in your own words
evergreen  connected to other notes
```

Three conditions — all three, or it does not get promoted:

- [ ] I rewrote it in my own words
- [ ] I added a `#topic/` tag
- [ ] I linked at least 2 related notes

## How the Library flows

```
00_Inbox     just dropped in (handle within 2 days)
10_Sources   attachments (automatic)
20_Zettel    promoted notes · MOCs
30_Archive   kept, not searched, not moved
```

## Folders that are never auto-filed

Projects · Study · Archive · Templates are **excluded from auto-move.**
You manage the structure inside them yourself, and auto-move would fight you.

## frontmatter

| Field | Meaning |
|---|---|
| `type` | Note type (required) |
| `status` | `draft` · `active` · `inbox` · `done` |
| `created` · `updated` | Dates (Linter keeps them current) |
| `review_at` | **When to look at it again** — folder hubs use this to tell you what is overdue |

> Leave `review_at` empty and the hub approximates with the last modified date.
> The more you fill in, the more accurate it gets.
