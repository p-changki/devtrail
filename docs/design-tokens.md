# 디자인 토큰

DevTrail은 표면이 다섯이다 — **CLI · 웹 대시보드 · 메뉴바 앱 · Obsidian 볼트 · 문서**.
표면마다 색을 따로 고르면 같은 「성공」이 네 가지 초록이 된다. 실제로 그랬다.

이 문서가 **단일 출처**다. 새 UI를 만들 때 색을 고르지 말고 여기서 가져온다.

---

## 원칙

**1. 색이 아니라 의미를 쓴다.**
`#2f6b4f` 가 아니라 `accent`. 값이 바뀌어도 코드는 안 바뀐다.

**2. 표면별 접두사만 다르다.**
이름은 하나다 — `success` 는 어디서나 `success` 다.
CLI는 `C_SUCCESS`, 웹은 `--dt-success`, Swift는 `Color.dtSuccess`.

**3. 의미색은 강조색과 별개다.**
`accent` 는 브랜드, `success/warning/danger` 는 상태다.
상태를 강조로 쓰거나 그 반대로 쓰지 않는다.

**4. Obsidian 안에서는 테마를 이긴다고 생각하지 않는다.**
볼트 CSS는 사용자 테마 변수 위에 얹는다. 우리 색을 강제하면 남의 테마가 깨진다.

---

## 왜 moss green 인가

자의적으로 고른 색이 아니다.

DevTrail의 핵심 개념은 **숙성**이다 — 노트가 `seedling → budding → evergreen` 으로
자란다. 이 은유가 시스템 전체를 관통한다(태그 `#상태/*`, 승격 게이트, 허브의
"밀린 것" 표시). **자라는 것을 다루는 도구의 강조색이 초록인 것은 근거가 있다.**

밝은 라임이나 형광 초록은 피했다. 터미널에서 매일 보는 색이라 눈에 부담이 없어야
하고, 흰 배경과 검은 배경 양쪽에서 대비가 서야 한다.

### 대비

모든 조합이 **WCAG AA(4.5:1)** 를 통과한다. 최저는 `ink-faint` 의 4.51:1 이다.

| 조합 | 라이트 | 다크 |
|---|---|---|
| `ink` / `bg` | 15.63 | 15.49 |
| `ink-muted` / `bg` | 6.97 | 8.25 |
| `ink-faint` / `bg` | **4.51** | 4.93 |
| `accent` / `surface` | 6.29 | 8.17 |
| `warning` / `surface` | 5.35 | 7.80 |
| `danger` / `surface` | 7.29 | 6.61 |
| `info` / `surface` | 7.39 | 8.05 |

`ink-faint` 는 처음에 `#7b877f` 였는데 3.50:1 이라 AA에 못 미쳤다.
11.5px 라벨에 쓰는 색이라 "큰 글자 예외"가 적용되지 않는다. `#68756c` 로 낮췄다.

**토큰을 바꿀 때는 대비를 다시 잰다.** 눈으로 괜찮아 보여도 수치가 답이다.

> `success` 와 `accent` 가 같은 값인 것은 의도다. 브랜드가 곧 "잘 됐다"는 신호다.
> 다만 **이름은 나눠 쓴다** — 나중에 갈라질 수 있고, 코드가 의도를 드러내야 한다.

## 표면별 매핑

### CLI (`lib/common.sh`)

터미널은 16색만 믿을 수 있다. 24비트 색은 쓰지 않는다 —
SSH·tmux·구형 터미널에서 깨진다.

| 토큰 | ANSI | 변수 |
|---|---|---|
| `accent` · `success` | `32` 초록 | `C_SUCCESS` |
| `warning` | `33` 노랑 | `C_WARNING` |
| `danger` | `31` 빨강 | `C_DANGER` |
| `info` | `34` 파랑 | `C_INFO` |
| `ink-muted` | `2` dim | `C_MUTED` |
| — | `1` bold | `C_BOLD` |

`NO_COLOR` 가 설정되거나 stdout이 TTY가 아니면 **전부 빈 문자열**이 된다.
파이프로 넘길 때 이스케이프가 섞이면 안 된다.

### 기호

색만으로 구분하지 않는다. 색맹 사용자와 색 없는 터미널을 위해 **기호를 함께** 쓴다.

| 의미 | 기호 | 함수 |
|---|---|---|
| 성공 | `✅` | `ok` |
| 경고 | `⚠️` | `warn` |
| 실패 | `❌` | `fail` |
| 단계 | `▶` | `step` |
| 보조 | (없음) | `dim` |

### 웹 대시보드 (`templates/dashboard/index.html`)

CSS 변수는 `--dt-` 접두사를 쓴다. Obsidian이나 다른 스타일과 섞이지 않게.

```css
:root {
  --dt-ink: #16201a;
  --dt-accent: #2f6b4f;
  /* … */
}
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { --dt-ink: #e5ece7; /* … */ }
}
:root[data-theme="dark"] { --dt-ink: #e5ece7; /* … */ }
```

**세 블록이 다 필요하다.** 시스템 기본(스탬프 없음) · 명시적 다크 · 명시적 라이트
세 상태가 있고, 하나라도 빠지면 한쪽 테마의 글자가 다른 쪽 배경에 얹힌다.

### 메뉴바 앱 (`app/Sources/DevTrailApp/`)

SwiftUI의 시맨틱 색을 우선한다 — 시스템 다크모드를 자동으로 따른다.
우리 색이 필요한 곳만 확장으로 정의한다.

| 토큰 | SwiftUI |
|---|---|
| `ink` | `.primary` |
| `ink-muted` | `.secondary` |
| `ink-faint` | `.tertiary` |
| `success` | `Color.dtSuccess` |
| `warning` | `Color.dtWarning` |
| `danger` | `Color.dtDanger` |

### Obsidian 볼트 (`preset/obsidian/snippets/devtrail.css`)

**여기서는 우리 색을 강제하지 않는다.** 사용자 테마 변수를 쓴다.

| 용도 | 변수 |
|---|---|
| 텍스트 | `var(--text-normal)` |
| 보조 | `var(--text-muted)` |
| 강조 | `var(--interactive-accent)` |
| 배경 | `var(--background-secondary)` |
| 경계 | `var(--background-modifier-border)` |

사용자가 Blue Topaz를 쓰든 기본 테마를 쓰든 **그 테마 안에서 자연스러워야** 한다.
DevTrail 색을 박으면 남의 볼트가 우리 것처럼 보인다.

## 타이포그래피

### 원칙

터미널과 볼트는 **사용자 설정을 존중한다.** 폰트를 강제하지 않는다.
문서(웹 대시보드 · 명세서)에서만 지정한다.

### 문서 표면

| 역할 | 폰트 | 왜 |
|---|---|---|
| 제목 | `Noto Serif KR` | 한글 세리프. 문서에 무게를 준다 |
| 본문 | `IBM Plex Sans KR` | 한글·라틴 모두 갖춘 기술 문서용 |
| 데이터 | `IBM Plex Mono` | 본문과 같은 가족이라 섞여도 어긋나지 않는다 |

**한글이 주 언어다.** 라틴 전용 폰트를 고르면 한글이 시스템 폰트로 폴백해
제목과 본문의 인상이 따로 논다. 한글을 지원하는 짝을 고른다.

### 스케일

| 역할 | 크기 | 행간 | 자간 |
|---|---|---|---|
| h1 | `clamp(30px, 5vw, 44px)` | 1.32 | −0.02em |
| h2 | `clamp(23px, 3.2vw, 29px)` | 1.32 | −0.02em |
| h3 | 19px | 1.32 | −0.02em |
| 본문 | 16px | **1.72** | −0.003em |
| 표 · 캡션 | 14.5px | 1.6 | 0 |
| 라벨 | 11.5px | 1.4 | **+0.07em** |
| 코드 | 0.875em | 1.5 | 0 |

**한글 본문은 행간이 넉넉해야 한다.** 라틴보다 글자가 빽빽해서 1.5로는 답답하다.
작은 라벨은 자간을 벌린다 — 한글은 작아지면 뭉친다.

### 폭

본문은 **65~68자**에서 줄바꿈한다. 그보다 길면 다음 줄을 찾기 어렵다.
표 · 코드 · 다이어그램은 예외이고, 대신 **자기 컨테이너에서 가로 스크롤**한다.
페이지 본문이 좌우로 스크롤되면 안 된다.

## 간격

4px 배수를 쓴다. 임의값을 쓰지 않는다.

| 이름 | 값 | 용도 |
|---|---|---|
| `xs` | 4px | 아이콘과 글자 사이 |
| `sm` | 8px | 관련된 요소 사이 |
| `md` | 12px | 카드 내부 |
| `lg` | 20px | 섹션 내부 |
| `xl` | 34px | 섹션 사이 |

레이아웃은 **flex/grid + gap** 으로 만든다. 요소마다 margin을 주면
서로 상쇄되거나 겹쳐서 결국 값을 못 믿게 된다.

---

## 금지

- **표면에서 색을 새로 고르는 것.** 필요하면 이 문서에 먼저 추가한다
- **의미색을 장식으로 쓰는 것.** 빨강은 실패지 강조가 아니다
- **CLI에서 24비트 색.** 16색만 쓴다
- **Obsidian CSS에 DevTrail 색 하드코딩.** 테마 변수를 쓴다
- **색만으로 정보 전달.** 기호나 텍스트를 함께 쓴다
- **미디어쿼리 안에서만 색 정의.** 시스템 기본 상태에서 적용되지 않는다

---

## 바꾸려면

1. 이 문서를 먼저 고친다
2. 다섯 표면을 전부 확인한다 — 하나만 바꾸면 다시 갈라진다
3. 라이트·다크 양쪽에서 대비를 확인한다
