# 0003. CLI 가 노트를 쓸 수 있다 — 좁고 되돌릴 수 있는 통로 하나

- 상태: 채택
- 날짜: 2026-08-22
- 관련: [0002 Command Center](./0002-command-center.md)

## 무엇이 문제였나

ADR 0002 는 **Templater / Shell commands 를 쓰기의 유일한 통로**로 정했다.
그 결정은 지금도 옳다 — 노트 형식이 두 곳에서 만들어지면 반드시 어긋난다.

그런데 그 통로는 **Obsidian 이 켜져 있어야** 열린다. 링크 하나를 받아두려고
Obsidian 을 띄우는 것은 도구가 사람을 기다리게 하는 일이다.

## 결정

**승인된 CLI 캡처 명령 하나만** 볼트에 쓸 수 있다.

```
Templater            Obsidian 안에서의 노트 생성    (기존)
devtrail capture …   Obsidian 없이, --apply 로만    (신설)
Swift 앱             쓰지 않는다 — CLI 를 부른다
Command Center       쓰지 않는다 — 읽기 모델이다
```

### 왜 경계를 넓히면서도 안전한가

이 통로는 네 가지로 묶여 있다.

1. **기본이 dry-run** — `--apply` 없이는 파일이 생기지 않는다
2. **저널** — 모든 생성이 `devtrail undo` 로 사라진다
3. **원자적** — 준비·검증을 다 마친 뒤에만 쓴다. 실패하면 아무것도 남기지 않는다
4. **템플릿 단일 출처** — 프런트매터와 본문 골격은 볼트의 템플릿에서 온다.
   CLI 가 자기 형식을 따로 만들지 않는다

⚠️ 이 네 가지 중 하나라도 없으면 통로를 열지 않는다. "임시로" 예외를 두면
그게 두 번째 쓰기 출처가 되고, 그때부터 노트 형식은 아무도 모르게 갈린다.

## AI 분석은 CLI 가 하지 않는다

유튜브 skill 의 여섯 단계 중 **네 번째(분석)** 는 자막을 읽고 한 줄 요약과
"나에게 적용할 점" 을 쓰는 일이다. bash 가 할 수 없고, 흉내 내서도 안 된다.

그래서 CLI 캡처는 **받아두기까지**다:

```
CLI      URL · 제목 · 채널 · 저장일 · status: inbox
skill    자막을 읽고 분석 칸을 채운다 (나중에, 사람이 부를 때)
```

템플릿의 기본 `status` 가 이미 `inbox` 다. 캡처는 "받아둔 것" 이고 분석은
아직 안 한 것 — 이 설계에 정확히 맞는다.

⚠️ 분석 칸을 그럴듯한 문장으로 채우지 않는다. 빈 칸은 "아직 안 했다" 는
사실이고, 지어낸 요약은 거짓이다. 빈 칸이 낫다.

## 네트워크

- URL 을 붙여넣는 것만으로 요청하지 않는다
- 사용자가 저장을 누를 때만, 그리고 **메타데이터만** 가져온다
- 실패하면 URL 만으로 저장한다 — 링크를 잃는 것보다 낫다
- 자막 전문을 노트에 옮기지 않는다

## 집계는 두 벌이다 — 계약 테스트로 묶는다

메뉴바 앱이 Obsidian 없이 상태를 보여주려면 CLI 가 노트를 세야 한다.
그 규칙은 이미 `plugin/main.js` 의 `collect()` 에 있다.

플러그인이 CLI 를 부르게 하는 편이 이론상 낫지만, Obsidian 안에서는
shell commands 를 거쳐야 해 느리고 취약하다. **두 벌을 두되, 같은 볼트에서
두 구현이 다른 답을 내면 테스트가 빨간불이 되게 한다.**

⚠️ 이 저장소는 `dirs.devlog` 의 기본값을 네 곳이 각자 갖고 있어 같은 결함을
   네 번 고쳤다. 두 벌을 허용하는 이번 결정은 **계약 테스트가 있는 동안에만**
   유효하다. 테스트가 사라지면 이 결정도 무효다.

## 되돌릴 조건

- 캡처 대상이 셋을 넘으면 — 그때는 공통 캡처 골격이 필요하다
- CLI 가 만든 노트와 Templater 가 만든 노트가 실제로 어긋나면
- 집계 계약 테스트가 유지 불가능해지면 — 그때는 플러그인이 CLI 를 부른다
