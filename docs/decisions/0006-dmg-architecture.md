# 0006 부록 — DMG 배포 아키텍처

> [ADR 0006](./0006-dmg-distribution.md) 의 상세 설계. **제안 상태**이며
> 구현을 시작하지 않는다.

## 1. 지금 무엇이 어디에 있나

```
사용자 Mac
├── ~/.devtrail/
│   ├── devtrail.config.json     설정 (볼트 경로·언어·GitHub 계정)
│   └── journal/<작업ID>/         되돌리기 기록
├── <저장소>/                     ← git clone 한 것
│   ├── bin/devtrail             CLI 진입점 (bash)
│   ├── lib/*.sh                 10,992줄 — jq 247회
│   ├── lib/**/*.py              1,827줄 — 설정·허브 생성, 볼트 진단
│   ├── plugin/                  Obsidian 플러그인 (2,157줄, files.json 이 정본)
│   ├── templates/               볼트 템플릿
│   └── app/                     Swift 메뉴바 앱 (1,367줄, macOS 14+)
└── <볼트>/
    ├── .obsidian/plugins/devtrail-command-center/   ← 배포 대상
    └── notes/…                                       ← 사용자 것. 건드리지 않는다
```

**저장소가 런타임 자산이다.** 사용자는 clone 한 디렉터리를 지워선 안 된다 —
`bin/devtrail` 이 거기 있고, 플러그인 원본도 거기 있다. 비개발자에게 이 사실은
설명할 수 없다.

## 2. 목표 구조

```
/Applications/DevTrail.app/
└── Contents/
    ├── MacOS/DevTrail              메뉴바 앱 + 온보딩 UI (Swift)
    ├── Resources/
    │   ├── cli/                    bin/devtrail + lib/*.sh  (그대로 이사)
    │   ├── plugin/                 files.json 이 정본 (그대로)
    │   ├── templates/              볼트 템플릿 (그대로)
    │   └── release.json            릴리즈 매니페스트 (신규)
    └── Helpers/devtrail-helper     python3 를 대체하는 Swift 바이너리 (신규)
```

사용자 데이터의 위치는 **바뀌지 않는다**: `~/.devtrail/`, 볼트, 저널 그대로.
즉 기존 CLI 사용자와 앱 사용자가 **같은 설정을 공유**한다.

## 3. `python3` 를 어떻게 걷어내는가

### 대체 대상 — 8파일 1,827줄

| `lib/snapshot.py` | 203 | 볼트 상태 → JSON (메뉴바용) | **이미 `Snapshot.swift` 존재** |

전부 **JSON 생성 · 텍스트 생성 · 파일 순회**다. Foundation 만으로 된다.
새 의존성이 필요 없다.

⚠️ `lib/gen/i18n.py` 는 **직접 호출되지 않는다** — hotkeys·hubs·hub 가
`import` 한다. 그래서 계약 테스트는 이 파일 단독이 아니라 **소비자를 통해**
세운다.

### 여기 없는 9번째 파일 — `templates/dashboard/server.py`

| | |
|---|---|
| 줄 | 280 |
| 무엇 | `devtrail dashboard` 가 띄우는 **로컬 HTTP 서버**. 화이트리스트 명령을 토큰으로 실행 |
| 왜 다른가 | 나머지 8개는 JSON·텍스트를 만들고 끝난다. 이건 서버 + 명령 실행이다 |
| 어디로 가나 | `templates/` 이므로 **사용자 볼트로 복사된다** |

Swift 이관 난이도가 다르고, **애초에 DMG 시대에 이 기능이 필요한지**가
먼저다. 메뉴바 앱과 Command Center 가 상태·실행·설정을 이미 다루는 것으로
보인다 — 겹치는 화면을 두 벌 유지하면 둘 다 낡는다.

**M1~M3 의 범위에 넣지 않는다.** D5 가 정해질 때까지 `devtrail dashboard` 는
`python3` 를 요구하는 채로 둔다 — 그리고 그 사실을 `doctor` 가 말하게 한다.

### 호출 규약 — shell 은 거의 그대로

```bash
# before
python3 "$DEVTRAIL_ROOT/lib/gen/hotkeys.py" templater --vault "$v"

# after
"$DT_HELPER" gen-hotkeys templater --vault "$v"
```

`DT_HELPER` 해석 순서:

1. `$DT_HELPER_OVERRIDE` (테스트용 — `DT_CC_SRC_OVERRIDE` 와 같은 방식)
2. `.app/Contents/Helpers/devtrail-helper`
3. 저장소의 빌드 산출물
4. **없으면 `python3` 로 폴백** ← 기존 Git 설치형 사용자가 아무것도 잃지 않는 이유

⚠️ 폴백을 조용히 하지 않는다. 어느 경로를 썼는지 `devtrail doctor` 가 말한다.

#### 숨은 입력을 전부 못 박았다

`DEVTRAIL_LANG` · `LC_ALL` · `TZ` · `DT_DATE` · `DT_HUB_*` · **파일 mtime** ·

#### 시계 이음새를 둬야 했다

`scan.py` 의 `role_candidates` 는 "최근에 손댔는가"로 점수를 곱하는데,
그 판정이 **현재 시각**에 걸린다. 실측:

고정하지 않으면 이 골든은 **한 달 뒤 저절로 깨진다.** 그래서 `scan.py` 에
`DT_NOW`, `snapshot.py` 에 `cfg.now_ms` 를 뒀다. 둘 다 **미설정 시 예전
그대로**이고, 테스트가 그것도 단언한다 — 기본 동작을 바꿨다면 그건
이음새가 아니라 변경이다.

| | |
|---|---|
| 이관 | `smartenv` (115줄) → `SmartEnv.swift` |
| 결과 | 골든 3건 **바이트 동일** |

#### 가장 큰 난점은 로직이 아니라 **JSON 직렬화**였다

python 의 `dict` 는 **삽입 순서**를 지키고, 그 순서가 그대로 출력에 나온다.
실제 골든:

```json
{
  "smart_sources": { … },
  "other_key": "건드리면 안 된다",   ← 기존 파일의 순서 그대로
  "is_obsidian_vault": true          ← 나중에 붙은 것이 맨 끝
}
```

Foundation 의 `JSONSerialization` 은 순서를 보장하지 않고, `JSONEncoder` 의
`.sortedKeys` 는 알파벳순으로 **바꿔 버린다.** 둘 다 다른 파일을 만든다 —
사용자 설정 파일에서 "키 순서만 다름" 은 다름이다.

그래서 순서를 지키는 JSON 값·파서·writer 를 직접 뒀다
(`JSON.swift` · `JSONParser.swift`). **8개 생성기 전부의 토대**이고,
여기가 틀리면 전부 틀린다. python 의 `json.dumps(ensure_ascii=False,
indent=2)` 를 정확히 재현한다 — 한글은 그대로, 들여쓰기 2칸, `": "` 구분.

#### 게이트가 조용히 건너뛰지 않게 했다

`run.sh` 의 swift 단계는 `all` 에서만 돌고 release 를 만든다 — 일상
게이트(`fast`)에서는 헬퍼 대조가 **통째로 건너뛰어진다.** 그래서 계약
테스트가 **직접 빌드**한다 (소스가 더 새로우면 재빌드, 증분 1초 안팎).

**게이트가 있는데 안 도는 것은 게이트가 없는 것보다 나쁘다** — 있다고
믿게 되기 때문이다.

그리고 **아직 이관하지 않은 케이스를 세어서 말한다.** 침묵하면 "다 됐다"
로 읽힌다.

#### 변이 6/6 빨간불

`indent 2→4` · 키를 알파벳순으로 · 비ASCII 를 `\u` 로 · `setDefault` 가
덮어씀 · 공백 트림 제거 · 두 번 도는 순회를 한 번으로 합침.

마지막 둘은 로직 이관에서 실제로 틀리기 쉬운 자리다 — python 은
`no_index` 를 전부 훑은 **뒤** `personal` 을 훑는데, 한 번에 합치면
제외 폴더의 **순서**가 달라진다.

#### 곁들여 잡은 것 — 무효 픽스처

`smartenv` 의 병합 케이스가 **텍스트 파일**을 기존 설정으로 줬다.
`json.load` 가 실패해 `{}` 로 떨어졌고, 병합 가지를 한 번도 안 탔다 —
merge 골든이 new 골든과 **글자 하나까지 같았다.** 통과하는데 아무것도
안 지키는 케이스였다. JSON 픽스처로 고치자 순서·트림·`setdefault` 보존이
전부 드러났고, 그 덕에 위 변이 셋을 시험할 수 있게 됐다.

그 계약을 지키는 테스트가 절반은 헛돌고 있었다.

#### 픽스처를 보강했다

- `CFG_PROJ` — `project_groups` 에 실제 키 + wildcard(`acme-*`) + 한글 레포
- `EXIST_ANM_OURS` — **우리 태그**(`#type/devlog`)를 이미 다른 폴더로 라우팅 중
- `tests/fixtures/tree-edge.json` — 프리셋이 못 지나는 가지를 태우는 **합성 트리**:
  `no_automove` 부모 + 태그 달린 자식, 중복 태그, 슬래시 없는 태그

마지막 항목은 두 번 고쳐야 했다. `flat` 하나로는 부족했다 — 알파벳순으로도
`project/…` 보다 앞이라 구체성 `-1` 을 `0` 으로 바꿔도 순서가 같았다.
`project` **뒤로** 정렬되는 `zflat` 을 더하고 나서야 구별됐다.

**변이 8/8 빨간불.**

**여기서도 한 번 더 헛다리를 짚었다.** 점유 대상으로 개발일지(`D`)를

했다 — 정렬 변이가 그대로 살아남았다. 개발메모(`M`)로 바꾸자 fallback
재배정(`Y`)이 일어나며 잡혔다.

#### 이 생성기가 지키는 것

#### ⚠️ 그래도 실제 이관 버그가 하나 나왔다 — 반올림

python 의 `round(x, 1)` 을 Swift 로 `(v * 10).rounded() / 10` 이라 옮겼다.
**두 가지가 어긋난다:**

1. Swift 의 `.rounded()` 는 half-away-from-zero, python 은 **half-to-even**
   (은행가 반올림)이다 — `round(0.25, 1)` → python `0.2` · Swift `0.3`
2. `× 10` 이 부동소수 오차를 만든다 — `33.35 * 10` 은 `333.49999999999994`
   라 333 으로 내려가지만, python 은 실제 double 값(`33.3500000000000014`)을
   보고 `33.4` 를 낸다

실측: 시험한 5개 값 중 **4개가 달랐다.** `String(format: "%.1f", v)` 는
C 의 정확한 십진 변환 + half-to-even 이라 8/8 일치한다.

**이 버그는 기존 골든이 잡지 못했다.** 픽스처 값이 전부 소수 1자리라
반올림 자체가 무의미했기 때문이다. 변이(`반올림 제거`)가 살아남아서 알았고,
그제야 경계값 케이스를 넣었다.

> 갈래를 먼저 세어도 **값의 성질**은 따로 봐야 한다. "어떤 분기가 있나" 와
> "그 분기 안에서 어떤 값이 위험한가" 는 다른 질문이다.

— 아래 「D7-B」 참조.

⚠️ 연기의 대가를 분명히 적는다. python3 가 없는 Mac 에서:

| | |
|---|---|
| 생성기 8종 | **돈다** (헬퍼) |
| `devtrail scan`·`augment`·`obsidian apply` | **돈다** (가드만 완화하면) |
| `summary` · `daily` · 볼트 스크립트 | **안 돈다** |

그러므로 **M4 는 "비개발자가 끝까지 쓸 수 있다" 를 주장할 수 없다.**
"설치하고 실행해 Command Center 를 연다" 까지로 좁히고, 그 한계를 릴리스
노트에 적는다. 좁힌 범위를 넓게 말하지 않는 것이 이 단계의 정직함이다.

생성기 1,827줄을 옮긴 것은 가장 큰 덩어리였지만 전부는 아니었다.

### 이관 순서 — 계약을 먼저

```
1. 파일마다 "같은 입력 → 바이트 동일 출력" 고정 테스트 (python 기준)
2. 그 테스트를 Swift 헬퍼에도 그대로 통과시킴
3. shell 의 호출을 헬퍼로 교체
4. python 파일 삭제는 **마지막에**, 폴백이 필요 없다고 확인된 뒤
```

⚠️ 순서를 바꾸면 안 된다. 테스트 없이 옮기면 생성되는 설정이 **조용히**
달라지고, 사용자 볼트의 단축키·폴더매핑이 어긋난다. 이 저장소는
`lib/snapshot.py` ↔ 플러그인 `collect()` 계약 테스트로 같은 방식을 이미 썼다.

## 3-1. M1 에서 찾은 것 — 언어가 python 까지 전달되지 않는다

계약 테스트에 변이를 주입하다 드러났다. `i18n.py` 의 기본 언어를 `ko` → `en`
으로 바꿔도 테스트가 통과했다. 왜냐하면 테스트가 `DEVTRAIL_LANG` 을 **항상**
지정해 기본값 경로를 한 번도 안 탔기 때문이다.

그래서 실제 운영 경로를 추적했더니:

| | |
|---|---|
| `DEVTRAIL_LANG` 을 export 하는 곳 | `lib/init.sh:58`, `lib/setup/spec.sh:139` **둘뿐** |
| `devtrail augment` 가 넘기는 환경 | `DT_DATE` 하나 |
| `hubs.py` 가 언어를 얻는 법 | `i18n.T()` → `os.environ.get("DEVTRAIL_LANG", "ko")` |
| `hubs.py` 가 설정 파일의 `lang` 을 읽는가 | **아니다** (`argv` 로 받지만 언어에 쓰지 않는다) |

⇒ **`devtrail augment` 를 `init` 과 다른 셸에서 실행하면, 영어 사용자도
한국어 허브 문구를 받는다.** 셸 쪽은 `dt_lang()` 으로 설정을 읽어 en 인데,
python 쪽은 기본값 ko 로 떨어진다.

### 고쳤다 (2026-08-23)

`lib/common.sh` 이 i18n 을 로드한 직후, 해결된 언어를 **한 번만** export 한다:

```bash
DEVTRAIL_LANG="$(dt_lang)"
export DEVTRAIL_LANG
```

호출부 12곳에 흩뿌리지 않는다 — 하나를 빠뜨리면 같은 병이 재발한다.
`dt_lang` 은 이미 `DEVTRAIL_LANG` 을 1순위로 읽으므로 멱등이고,
`DEVTRAIL_LANG=en devtrail …` 같은 일회성 지정도 그대로 존중된다.

`tests/test-lang-propagation.sh` 가 지킨다. **문자열이 아니라 실제
서브프로세스가 받는 값**을 보고, 나아가 **생성기 출력이 실제로 달라지는지**
까지 본다 — "export 하는 줄이 있다" 는 그 줄이 도는지 말해 주지 않는다.
수정을 되돌리면 4개가 빨간불이 된다.

⚠️ **골든은 바뀌지 않았다.** 계약 테스트는 python 을 직접 부르므로 CLI 의
언어 전달과 무관하다. 즉 이 수정은 생성기의 **출력 계약을 건드리지 않았다** —
M2 의 이관 목표가 흔들리지 않는다.

### 아래는 당초 판단 (참고)

M1 의 목적은 **현재 동작을 바이트로 고정하는 것**이다. 여기서 언어 전달을
고치면 골든이 바뀌고, 이관(M2)의 목표가 "같은 출력"에서 "다른 출력"으로
흔들린다. **리팩터와 동작 수정을 같은 커밋에 섞지 않는다.**

대신 `DEVTRAIL_LANG` 이 **없는** 케이스를 골든에 넣어 그 경로를 고정했다.
Swift 헬퍼도 같은 기본값을 지켜야 한다 — 고치기로 정하기 전까지는.

⚠️ 이건 **별도 결정 사항**이다 (→ ADR 0006 D6).

`install-git-hooks.sh` 에서 이미 같은 원칙을 세웠다.

## 5-1. 번들 자산 — `jq` (D1, 2026-08-24 확정)

시스템 `jq` 에 **의존하지 않는다.** Apple 이 어느 macOS 부터 `/usr/bin/jq`
를 넣었는지 확인하지 못했고, 확인하지 못한 것에 기대지 않는다.

| | |
|---|---|
| 최소 macOS | **14** (Swift 앱의 현재 요구사항과 같다) |
| 번들 위치 | `Contents/Helpers/jq` |
| 아키텍처 | **universal (`arm64` + `x86_64`)** |
| 서명 | Developer ID — 앱과 함께 공증 대상 (M7) |
| 무결성 | 빌드 시점에 `sha256` 을 `release.json` 에 박고, **어긋나면 릴리스가 막힌다** (M6) |

⚠️ **universal 이 지금은 아니다.** 실측(2026-08-24):

```
lipo -archs app/.build/debug/DevTrailHelper → arm64
```

macOS 14 는 **Intel 맥도 지원한다.** `jq` 만 universal 로 만들어도 앱이
`arm64` 면 Intel 에서 뜨지 않는다 — **앱·헬퍼·jq 셋 다** 해당한다.
M4 의 명시적 항목으로 둔다.

⚠️ **라이선스는 확인 후에 적는다.** 로컬에 `jq` 라이선스 파일이 없어
(`/usr/bin/jq` 는 Apple 빌드) 지금 단정하지 않는다. 기억으로 적었다가 틀린
전례가 있다(`TRACKED_FIELDS`, 2026-08-24). **실제로 가져오는 시점에 원본
배포물의 라이선스 파일을 확인해 그대로 번들에 넣고 문서화한다.**

⚠️ **무결성은 사용자 기계가 아니라 빌드 시점에 지킨다.** "누락 시 안내"
만으로는 늦다 — 앱을 만들 때 해시를 고정하고 매니페스트와 대조한다.

## 6. 릴리즈 버전 계약

`VERSION` 하나가 정본이고, 나머지가 그것을 따른다.

```
VERSION (0.6.0)
 ├─ app/Package.swift · Info.plist   번들 버전
 ├─ plugin/manifest.json             플러그인 버전 (독립 SemVer, 매니페스트에 기록)
 ├─ templates/                       템플릿 세대
 └─ config schema version            설정 스키마 (현재 3)
```

`Resources/release.json`:

```json
{
  "schema": 1,
  "version": "0.6.0",
  "app": { "bundle_version": "0.6.0", "min_macos": "<D1 에서 확정>" },
  "plugin": { "id": "devtrail-command-center", "version": "0.14.0" },
  "config_schema": 3,
  "artifacts": [{ "name": "DevTrail-0.6.0.dmg", "sha256": "…", "size": 0 }]
}
```

**게이트가 이것을 소비한다** (M6): 태그 ↔ `VERSION` ↔ `release.json` ↔
`manifest.json` ↔ config schema 가 어긋나면 릴리스가 막힌다. 문서에 적기만
하면 곧 거짓말이 된다 — 이 저장소가 `check-ci-coverage.py` 로 배운 것이다.

## 6-1. M6 — 버전 계약 게이트 (2026-08-24 완료)

### 정본은 여섯 곳, 매니페스트는 그것을 **읽는다**

```
VERSION               제품 버전
plugin/manifest.json  플러그인 버전
plugin/files.json     배포 파일 목록
lib/migrate.sh        DT_SCHEMA (설정 스키마)
app/Package.swift     최소 macOS (D1: 14)
CHANGELOG.md          이 버전의 항목
        ↓  scripts/make-release-manifest.sh
release.json          ← 빌드 산출물. 커밋하지 않는다.
```

⚠️ 매니페스트가 값을 **정하지 않는다.** 정본에서 읽어 적을 뿐이다. 여기에
값을 적기 시작하면 일곱 번째 정본이 된다.

### 게이트가 막는 것 — 변이 8/8 확인

| 어긋남 | 결과 |
|---|---|
| `VERSION` 만 올리고 `CHANGELOG` 를 안 씀 | ✗ |
| `DT_SCHEMA` 와 `init` 의 `version` 이 갈림 | ✗ |
| `files.json` 이 **없는 파일**을 가리킴 | ✗ |
| **선언 안 된 파일**이 `plugin/` 에 있음 | ✗ |
| 매니페스트 생성 스크립트가 깨짐 | ✗ |
| 파일이 바뀌었는데 **해시가 안 따라감** | ✗ |
| `min_macos` 를 딴 데서 읽음 | ✗ |
| `release.json` 을 **커밋함** | ✗ |

네 번째가 특히 중요하다. `plugin/` 에 있지만 `files.json` 에 없는 파일은
**설치되지 않는다** — 개발자만 보고 사용자는 못 보는 코드가 생기고, 그
상태로 "동작한다" 고 말하게 된다.

여섯 번째는 무결성이다. 매니페스트만 갱신하고 파일을 안 바꾸는(또는 그
반대) 사고를 잡는다. **사용자 기계가 아니라 빌드 시점에 지킨다.**

### 만들 수 있다고 주장하지 않는다 — 만들어 본다

`verify-local.sh --release` 가 매니페스트를 **실제로 생성**한다. 릴리스
직전에 "생성이 깨져 있었다" 를 알게 되면 늦다.

## 6-2. M4 (1) — universal 빌드 · 헬퍼 번들 (2026-08-24)

### universal 이 왜 필수인가

최소 macOS 가 **14** 인데(D1), **macOS 14 는 Intel 맥도 지원한다.**
Apple Silicon 에서 빌드하면 기본이 `arm64` 하나라, 그대로 DMG 를 만들면
Intel 맥에서 **아예 열리지 않는다.**

⚠️ **만든 사람 기계에서는 영원히 재현되지 않는다.** 그래서 게이트가 유일한
방어다.

### 실측

```
swift build -c release --arch arm64 --arch x86_64   → 됨
lipo -archs DevTrailApp      → x86_64 arm64
lipo -archs DevTrailHelper   → x86_64 arm64
```

번들 산출물:

```
DevTrail.app/Contents/
  MacOS/DevTrail                 universal
  Helpers/devtrail-helper        universal
  Info.plist                     LSMinimumSystemVersion 14.0
  _CodeSignature/
```

### 게이트가 막는 것 — 변이 9/9

| 어긋남 | 결과 |
|---|---|
| 앱이 `arm64` 하나뿐 | ✗ |
| 헬퍼가 `arm64` 하나뿐 | ✗ |
| 헬퍼가 번들에 **없음** | ✗ |
| 헬퍼에 **실행 권한이 없음** | ✗ |
| `build.sh` 가 단일 아키텍처로 | ✗ |
| `build.sh` 가 **결과를 확인 안 함** | ✗ |
| `dt_helper` 가 **다른 경로**를 봄 | ✗ |
| `Package.swift` 만 macOS 15 로 | ✗ |
| `VERSION` 만 바뀌고 번들은 그대로 | ✗ |

### 소스가 아니라 **산출물**을 본다

"플래그를 줬다" 는 것과 "universal 이 나왔다" 는 다르다 — 툴체인이 조용히
호스트만 만들 수 있다. 그래서 `build.sh` 자신이 `lipo` 로 확인하고,
테스트는 **빌드된 `.app` 을 연다.**

같은 이유로 헬퍼는 "파일이 있다" 가 아니라 **실제로 실행해 본다.** 복사만
하고 실행 권한이 빠지거나 서명이 깨지는 경우를 잡는다.

### 서명은 안쪽부터

번들만 서명하면 `Contents/Helpers` 안의 실행 파일이 서명되지 않은 채 남고,
**공증(M7)에서 거부된다.** ad-hoc 이라도 지금부터 안쪽을 먼저 서명한다.

## 6-3. M4 (2) — `jq` 번들 (2026-08-24)

### 왜 넣는가

D1 이 정한 대로다. DMG 를 받는 사람에게 `jq` 가 있다고 가정할 수 없는데,
CLI 는 **40개 파일 139곳**에서 `jq` 를 부른다. 없으면 앱은 켜지고
**기능이 전부 죽는다.**

### 라이선스 — 확인하고 적는다

D1 은 "실제로 가져오는 시점에 원본 배포물의 라이선스를 확인한다" 고 미뤄
뒀다. 확인했다:

`jq-1.8.2` 의 `COPYING` 은 **MIT 하나가 아니다.** 다섯 블록이 한 파일에 있다.

| 블록 | 라이선스 |
|---|---|
| jq (Stephen Dolan, 2012) | MIT |
| decNumber (Lucent, 1991·1996·2000·2001) | 관대형 |
| ICU (IBM, 1995–2005) | ICU |
| Kungliga Tekniska Högskolan (2016) | BSD 3-clause |
| NetBSD `strptime()` | BSD |

GPL 은 없다. 전부 permissive 이고 **고지 의무**만 있다. 그래서 요약하지 않고
`COPYING` 을 **원본 그대로** `Contents/Resources/licenses/jq-COPYING.txt` 에
넣는다 — 게이트가 sha256 으로 원본임을 확인한다.

⚠️ 이 표는 **읽어서** 적었다. `TRACKED_FIELDS` 를 기억으로 적었다가 틀린
전례가 있다(2026-08-24). 정본은 번들 안의 파일이고, 이 표는 요약이다.

### 최소 macOS — D1 과 맞는지 확인했다

```
otool -l jq-macos-arm64  →  minos 14.0
otool -l jq-macos-amd64  →  minos 14.0
```

D1 의 macOS 14 와 **정확히 맞는다.** 우연히 맞은 것이므로 게이트로 못 박았다
— 락의 `min_macos` 가 `Package.swift` 의 최소보다 높으면 빌드가 선다. 앱은
뜨는데 `jq` 만 못 도는 기계가 생기면, 그때 나는 에러는 원인을 가리키지 않는다.

### 무결성 — 새 신뢰 기준점을 만들지 않는다

D1: "무결성은 사용자 기계가 아니라 **빌드 시점**에 지킨다."

```
vendor/jq/jq.lock.json     출처 · 슬라이스 sha256 · 라이선스 sha256 (커밋됨)
scripts/fetch-jq.sh        받아서 상류 해시와 대조 → lipo -create
vendor/jq/build/jq         universal 산출물 (gitignored)
```

우리가 만든 해시를 우리가 확인하는 순환을 피한다. 합친 universal 은
`lipo -thin` 으로 **다시 쪼개** 상류(`sha256sum.txt`)가 발표한 슬라이스
해시와 대조한다. 실측으로 되짚힌다:

```
lipo -thin arm64  → 2d75340b…  = 상류 jq-macos-arm64
lipo -thin x86_64 → e94b266e…  = 상류 jq-macos-amd64
lipo -create 는 결정론적       (같은 입력 → 같은 출력, 실측)
```

⚠️ **실린 `jq` 는 나중에 되짚을 수 없다.** 서명이 바이트를 바꾸고,
`codesign --remove-signature` 로 지워도 원본으로 **돌아오지 않는다**(실측).
그래서 무결성은 넣기 **전에** 확인해야 하고, `build.sh` 의 관문이 마지막
기회다. 관문을 `swift build` **앞**에 둔 이유이기도 하다 — 90초를 태우고
나서 말하면 늦고, 막혔을 때 기존 번들이 그대로 남는다.

### 네트워크는 갱신할 때만 쓴다

로컬 우선 정책상 평소 빌드가 네트워크에 묶이면 안 된다. `fetch-jq.sh` 는
산출물이 이미 락과 맞으면 **네트워크를 쓰지 않는다.** `curl` 을 PATH 에서
아예 없애고 돌려서 확인했다.

### 빌드 담당자의 전제조건 — 사용자 제약이 아니다

`fetch-jq.sh` 와 `build.sh` 는 **빌드하는 기계의 `jq`** 를 쓴다 (락 파일을
읽어야 하므로). 닭과 달걀처럼 보이지만 아니다:

| | `jq` 가 필요한가 |
|---|---|
| 앱을 **설치·사용**하는 사람 | **아니다** — 번들에 실려 나간다 |
| 앱을 **빌드**하는 사람 | 그렇다 (`swift`·`lipo`·`codesign` 과 같은 줄) |

이 표를 적어 두는 이유는, 나중에 "jq 를 번들에 넣는다면서 jq 를 요구하네" 로
읽힐 수 있어서다. 요구하는 쪽은 **빌드 환경**이다.

### 139곳을 고치지 않는다 — PATH 한 곳

`jq` 는 맨몸으로 불린다(`jq -r …`). 호출부를 하나씩 고치면 **다음에 새로
쓰는 곳에서 또 빠진다** — 이 저장소가 `dirs.devlog` 기본값으로 네 번 겪은
결함이다. `lib/common.sh` 진입점에서 번들 배치를 감지해 `Contents/Helpers`
를 `PATH` **앞**에 붙이고 끝낸다.

**앞**인 이유: DMG 를 받은 사람에게는 우리가 해시를 못 박고 실제로 돌려 본
그 버전이 돌아야 한다. 뒤에 붙이면 기계마다 다른 `jq` 가 잡히고, 판마다
출력이 조금씩 달라 "왜 저 사람 기계에서만" 이 된다. 번들이 아닐 때는
아무것도 하지 않는다 — 개발 중에는 각자의 `jq` 를 쓴다.

고쳤다. `codesign` 이 없으면 빌드하지 않고, 서명과 검증 **둘 다** 실패하면
세운다. 서명했다는 것과 서명이 유효하다는 것은 다르므로 둘을 따로 본다.

게이트도 문자열이 아니라 **행동**으로 확인한다 — 우리 번들에만 실패하는
가짜 `codesign` 을 `PATH` 에 심고 `build.sh` 를 실제로 돌린다.

|---|---|
| 서명 **검증** 실패를 무시 | ✗ |

원인을 정확히 가리키고, 문서가 말하는 계약과 코드가 같아진다. 다만 "변이가

## 6-4. M4 (3) — CLI 자산을 번들 안으로 (2026-08-24)

메뉴바 앱은 화면일 뿐이고 실제 일은 전부 CLI 가 한다. 앱만 배포하면 설치한
사람은 **"켜지는데 아무것도 안 되는"** 상태를 본다.

### 어디에 넣나 — `Resources` **바로 아래**

```
DevTrail.app/Contents/
  MacOS/DevTrail
  Helpers/          devtrail-helper · jq
  Resources/        bin lib plugin preset templates skills VERSION CHANGELOG.md
                    licenses/jq-COPYING.txt
```

한 겹 더(`Resources/cli/`) 넣으면 안 된다. `dt_helper` 가
`$DEVTRAIL_ROOT/../Helpers` 를 보므로 `Resources/cli/../Helpers` 가 되어
**헬퍼도 번들 `jq` 도 못 찾는다.** 게이트가 이 변이를 잡는다.

### 목록의 정본은 **코드**다

`build.sh` 가 여덟 가지를 복사한다. 문제는 나중에 누군가
`$DEVTRAIL_ROOT/foo` 를 새로 참조할 때다 — 저장소에서는 멀쩡히 돌고
**번들에서만** 죽는다.

그래서 `tests/check-bundle-assets.py` 가 `bin`·`lib` 소스에서
`$DEVTRAIL_ROOT/<무엇>` 을 훑어, 번들에 없는 것이 있으면 세운다. 빼는 것에는
이유를 적고, **이유가 사라지면 예외도 사라지게** 했다 (아무도 참조하지 않는
예외가 남아 있으면 게이트가 그것도 지적한다).

| 뺀 것 | 이유 |
|---|---|
| `app/` | `devtrail app` 은 개발자 명령(앱 자신을 빌드한다)이고, `dt_helper` 는 번들 `Contents/Helpers` 를 2순위로 먼저 본다 |
| `.git` | 설치본이 아니라 저장소의 것. `updatecmd.sh` 가 없을 때를 이미 가드한다 — 앱 업데이트는 M8 |

### 실측 — 옮긴 `.app` 에서

M4 (2) 의 `PATH` 기전은 **흉내 낸 하니스**로만 증명돼 있었다. 이제 빌드된
`.app` 을 **다른 경로로 복사해** 실제로 돌린다 (저장소와의 상대 위치가
달라지므로, 저장소에 기대고 있으면 드러난다):

| 확인 | 결과 |

### `DEVTRAIL_ROOT` 오염 — 두 겹으로 막는다

사용자 환경에 개발용 `DEVTRAIL_ROOT` 가 남아 있을 수 있다
(`launchctl setenv`, 터미널에서 띄운 경우). 그러면 번들 앱이 조용히
**저장소 코드**를 쓰고, 그 기계에서만 다르게 동작한다.

1. `bin/devtrail` 이 자기 위치에서 `DEVTRAIL_ROOT` 를 **무조건 다시 정한다**

2. 앱이 자식 환경에서 `DEVTRAIL_ROOT` · `DT_CC_SRC_OVERRIDE` ·

설정 위치(`DEVTRAIL_HOME`·`DEVTRAIL_CONFIG`)는 사용자의 정당한 선택이므로

그 어긋남이다. 사용자가 따로 설치한 CLI 는 터미널에서 그대로 쓰인다.

⚠️ `CLI.swift` 의 예전 주석은 **"2) 앱 번들 옆"** 이라고 적혀 있었는데 코드는

처음에 그렇게 적었는데 과소평가다. M7 에서 실제로 붙는 것은:

| M7 에서 추가되는 것 | 왜 한 줄이 아닌가 |
|---|---|
| **hardened runtime** (`--options runtime`) | 런타임 제약이 켜진다. 지금 도는 것이 그때 안 돌 수 있다 |
| **서명 순서** | 안쪽부터 → 바깥 순서를 공증이 강제한다. 지금 ad-hoc 에서 느슨하게 넘어간 것이 그때 걸린다 |
| **공증 업로드** (`notarytool submit --wait`) | 애플 서버가 판정한다. 거부 사유가 우리 코드 밖에 있을 수 있다 |
| **staple** | 공증 결과를 산출물에 박는다. 빠뜨리면 오프라인에서 막힌다 |
| **Gatekeeper 실물 QA** | 대체 불가 — 사람이 깨끗한 맥에서 봐야 한다 |

그래도 **구조를 먼저 고정하는 선택은 유효하다.** M7 때 구조 문제와 공증
문제를 섞지 않게 된다 — 그것이 이 단계의 목적이다.

### 지금 이 산출물의 자격

⚠️ **"내부 설치 구조 검증용" 이다.** 사용자에게 배포하지 않는다. 앱 · 헬퍼 ·
`jq` · CLI 자산이 실제로 **하나의 설치물로 묶이는지**, `Applications` 링크와
복원 경로가 맞는지를 확인하는 데까지만 쓴다.

⚠️ 그리고 이 사실을 **단언으로 못 박았다** — `서명이 ad-hoc 이다` ·
`Gatekeeper 가 아직 거부한다`. 아무도 "이제 배포해도 된다" 고 잘못 말하지
못한다. M7 에서 이 두 줄을 고치는 행위가 곧 **"배포 가능해졌다" 는 선언**이
된다.

### 산출물

```
dist/DevTrail-0.5.0.dmg      2,020,629 bytes · UDZO(압축 읽기전용)
  DevTrail.app               universal · jq · CLI 자산 포함
  Applications → /Applications
```

읽기 전용(UDZO)으로 만든다. 받은 사람이 내용을 바꿀 수 없다. `/Applications`
심볼릭 링크가 없으면 사람은 앱을 **어디로 끌어다 놓아야 하는지 모른다** —
DMG 배포의 사실상 표준이다.

### 만들어 두고 검사하지 않는다

`tests/test-dmg.sh` 가 **DMG 를 직접 만들고** 검사한다. 만들어 둔 것을 나중에
검사하는 순서로 두면 **앞 판의 DMG** 를 보면서 통과할 수 있다 — 산출물이
낡았는지 아무도 모른다. (헬퍼 계약 시험이 헬퍼를 직접 빌드하는 것과 같은
이유다.)

그래서 `verify-local.sh` 에는 DMG 단계를 **넣지 않았다.** 그 파일은 스스로
"검사 목록을 갖지 않는다" 고 못 박고 있고, 정본은 `tests/run.sh` 다.

## 6-6. M4 (4b) — 온보딩 (2026-08-24)

### 이미 있던 것은 건드리지 않았다

첫 실행 흐름은 이미 있었다: `devtrail setup status --json` 이 `configured:
false` 를 내면 셋업 버튼을 보여주고, 누르면 Terminal 에서 `devtrail init` 이
열린다. 근거도 코드에 적혀 있다 — *"init 은 대화형이다. 그 대화를 앱 안에 다시
만드는 것은 같은 것을 두 벌 관리하는 일이고, 둘이 어긋나는 순간 사용자가
다친다."* 맞는 판단이라 그대로 뒀다.

그리고 **새 볼트 / 기존 볼트 구분도 이미 된다** — 판정을 CLI 가 하고, 설정이
있으면 온보딩 화면 자체가 안 나온다. 따로 만들 것이 없었다.

### 실제로 빠져 있던 것 — DMG 사용자의 첫 번째 벽

DMG 로 받은 사람의 `PATH` 에는 `devtrail` 이 **없다.** 앱은 번들 안의 CLI 를
절대경로로 부르니 잘 돈다. 그런데 그 사람이 터미널에서 `devtrail activity` 를
치면 **없다.**

`devtrail link <status|create>` 를 더했다.

### 로직은 CLI 에, 화면은 그리기만

이 저장소의 규칙이다 — **UI 에 로직을 넣지 말 것.** 같은 판정을 CLI 와 앱에 두
벌 두면 반드시 어긋나고, 어긋난 쪽이 화면이면 사용자가 먼저 본다.

```
devtrail link status --json   →  { state, path, self, target, on_path }
devtrail link create              만든다 (덮어쓰지 않는다)
```

앱은 `state` 를 읽어 그리기만 한다. 게이트가 이것도 단언한다 — 화면이
파일시스템을 직접 보거나 상태를 스스로 계산하면 빨간불이다.

### ⚠️ 덮어쓰지 않는다 (D4 공존)

이미 `devtrail` 이 있으면 그건 **그 사람이 만든 것**이다. 앱이 자기 것으로
바꿔치기하면 터미널에서 쓰던 버전이 말없이 달라지고, 되돌리는 법도 알려주지
못한다.

| 상태 | 하는 일 |
|---|---|
| `absent` | 만든다 |
| `linked_here` | 이미 연결됨 — 아무것도 안 한다 |
| `linked_other` | **거부.** 그대로 두고, 앱은 번들 것을 쓴다고 말한다 |
| `occupied` (링크 아닌 파일) | **거부.** 손대지 않는다 |

개발 기계에서 바로 확인됐다 — 실제 기존 설치
(`~/.devtrail/src/bin/devtrail`)를 `linked_other` 로 잡고 손대지 않았다.

⚠️ `~/.local/bin` 이 `PATH` 에 없으면 링크를 만들어도 소용이 없다. 그 사실을
감추지 않고 함께 말한다.

### 번들에서 거짓 안내를 하지 않는다

CLI 를 못 찾았을 때 화면은 `curl … install.sh | bash` 를 보여주고 있었다.
M4-3 이후 **앱 안에 CLI 가 실려 나가므로**, 번들로 실행 중인데 CLI 가 없다면

## 6-7. D7-B — 가드 완화 · 인라인 python 대체 (2026-08-24)

### 왜 이것부터인가

**헬퍼로 돌 수 있는 기능을 `python3` 이 없다는 이유로 막는 것은 사용자
버그다.** 생성기 8종은 M2·M3 에서 Swift 로 옮겼는데, 가드는 계속
`python3` 을 요구하고 있었다.

범위는 **①+②** — 저장소 내부 코드라 테스트·되돌리기 범위가 분명하다.
③(볼트 템플릿)은 이미 사용자 볼트에 복사된 계약이라 **D7-C 로 분리**한다.

### ① 가드 — `require_gen`

```
dt_helper 있음        → 통과
헬퍼 없고 python3 있음 → 통과 (폴백 그대로)
둘 다 없음            → 무엇이 없는지 말하고 실패
```

5곳을 `require_bins jq python3` → `require_bins jq; require_gen` 로 바꿨다:
`scancmd` · `obsidian` · `augmentcmd` · `cc/snapshot` · `capturecmd`.

⚠️ `obsidian.sh` 는 자기 파일에 `python3` 도 `dt_gen` 도 없었다. **병합기**
(`lib/merge/*.sh`)가 `dt_gen` 을 부르기 때문이었다 — 가드를 완화하기 전에
5개 파일을 하나씩 열어 확인했다. 짐작으로 풀면 필요한 가드를 지운다.

### ② 인라인 python

| 자리 | 전 | 후 |
|---|---|---|
| `oa_open` URL 인코딩 | `urllib.parse.quote(safe="")` | `jq -rn '$s\|@uri'` |
| `oa_vault_id` md5 | (이미 `md5` 우선) | 그대로 — python 은 3순위 |
| `_cap_render` | `python3` + `re.sub` | `awk` |

**대체재가 같은 결과를 내는지 실측했다.** 기억으로 적지 않았다:

```
jq @uri  vs  python quote(safe="")   8/8 일치
  /Users/a/Vault · /한글/볼트 이름 · ~._- · !()* · ' · %#?& · += · @:
md5      vs  python hashlib.md5      3/3 일치 (빈 문자열 · 한글 포함)
```

`oa_open` 은 `python3` 이 없으면 **볼트를 지정하지 못한 채** Obsidian 만
열렸다. 이제 지정해서 연다.

### ⚠️ 값을 문자 그대로 넣는다 — 옮기며 버그를 하나 고쳤다

정규식 치환은 **치환문자열의 특수문자를 해석한다.** python 의 `re.sub` 는
`\1` 을, awk 의 `gsub` 는 `&` 를 특수 취급한다.

제목에 `\1` 이 들어 있으면 **예전 python 판은 크래시했다**
(`invalid group reference`). awk 판은 `match` + `substr` 로 잘라 붙여
문자 그대로 넣는다 — 둘 다 막았다.

### ⚠️ 무한 루프를 만들었다가 잡았다

변이 주입 중 `line = splice(...)` 를 `line = line` 으로 바꿨더니
`while (match(...))` 가 **같은 자리를 영원히 다시 찾아** CPU 한 코어를 물었다
(2026-08-24, 실제 사용자 기계에서).

두 곳을 고쳤다:

1. **렌더에 진행 보장** — 길이가 줄지 않으면 `break`. 정상 동작에서는
   `<%…%>` 가 값으로 바뀌므로 항상 줄고, 안 줄면 뒤의 `<%` 검사가
   **소리내어** 실패시킨다.
2. **변이 하니스에 타임아웃** — 변이는 멈추지 않을 수 있다. 90초에 끊고
   자식까지 정리한다.

⚠️ 교훈: **변이 주입은 프로그램을 멈추지 않게 만들 수 있다.** 하니스에
시간 제한이 없으면 그 대가를 사람이 치른다.

### ⚠️ 실패 전에 일부를 출력하고 있었다

첫 awk 판은 검사하며 출력해서, 문법이 남은 줄을 만나기 **전까지의 내용을
이미 뱉은** 뒤 실패했다. python 판은 전체를 검사하고 아무것도 안 낸다.

반쯤 쓰인 노트가 남으면 다음 사람이 그것을 진짜라고 읽는다. 검사를 **끝까지
먼저** 하도록 고쳤고, `아무것도 출력하지 않는다` 를 단언으로 못 박았다.

### 게이트 — 변이 10/10

### 결정 — D7-C 이관 대신 **선택적 안내** (2026-08-24)

D7-C(볼트 스크립트를 python 에서 떼어내기) 마이그레이션 설계를 **지금 하지
않는다.** 이미 사용자 볼트에 설치된 스크립트의 계약을 바꾸는 일이라 무겁고,
그것 때문에 출시가 밀리는 것은 비용이 이득보다 크다.

대신 **제한을 숨기지 않고 말한다.**

| 원칙 | 뜻 |
|---|---|
| 핵심 기능은 `python3` 없이 쓴다 | D7-B 로 이미 그렇다 |
| **그 기능을 처음 누를 때만** 안내 | 켜자마자 경고를 띄우지 않는다 — 안 쓸 사람에게는 없는 문제다 |
| 설치 방법 보기 · 다시 확인 | 사용자가 스스로 고칠 길을 준다 |
| **자동 설치를 하지 않는다** | 남의 기계에 무엇을 까는 것은 사용자 결정이다 |
| **사용자 템플릿을 강제로 덮어쓰지 않는다** | 볼트 안의 것은 그 사람의 것이다 (D4 와 같은 원칙) |

이러면 출시를 불필요하게 늦추지 않으면서, 기능 제한도 숨기지 않는다.
"좁힌 범위를 넓게 말하지 않는다" 는 이 문서의 원칙과도 맞는다.

⚠️ 이 UX 는 **깨끗한 맥 QA 뒤에** 만든다. 무엇이 실제로 아픈지 보고 나서
안내 문구를 정하는 편이 낫다 — 지금 쓰면 짐작으로 쓰게 된다.

D7-C 는 **폐기가 아니라 보류**다. 나중에 볼트 스크립트를 손볼 이유가 따로
생기면 그때 함께 다룬다.
