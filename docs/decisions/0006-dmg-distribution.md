## 무엇이 문제인가

지금 DevTrail 을 쓰려면 이 순서를 밟아야 한다:

```
git clone → 터미널 → ./install.sh → devtrail init → …
```

비개발자에게는 **첫 줄에서 끝난다.** git 도, 터미널도, 그 안에서 무엇을
쳐야 하는지도 모른다. 목표 흐름은 이것이다:

```
DMG 다운로드 → Applications 로 드래그 → 실행
→ 새 볼트 만들기 / 기존 볼트 연결 → 안내대로 Obsidian 열기 → 사용
```

## 무엇을 실측했나 (2026-08-23, macOS 26.6)

추측으로 대안을 비교하면 문서가 곧 틀린다. 먼저 쟀다.

### 의존성이 비개발자 Mac 에 있는가

| 의존성 | 있나 | 근거 | 판정 |
|---|---|---|---|
| `bash` 3.2 | **있다** | Apple 이 `/bin/bash` 로 항상 제공 | 문제 없음 |
| `jq` | **있다** — 이 기계(macOS 26.6)에서 확인 | `/usr/bin/jq` = `jq-1.7.1-apple`, `Identifier=com.apple.jq`, SIP 보호 `/usr/bin`, root:wheel | ⚠️ **어느 macOS 부터인지는 미확인** |
| `python3` | **아니다** | `/usr/bin/python3` 는 **CLT 셰임**이다. Xcode·Command Line Tools 가 없으면 실행 시 설치 다이얼로그가 뜬다 | **치명적 차단** |
| `git` | **아니다** | 같은 CLT 셰임 | 설치 경로에서만 문제 |

`codesign -dv /usr/bin/jq` → `Identifier=com.apple.jq`. `/usr/bin` 은 SIP 로
보호되어 Homebrew 가 쓸 수 없는 경로다. **jq 는 Apple 이 넣은 것이다.**

⚠️ 이 기계는 macOS 26.6 이다. **jq 가 어느 버전부터 들어갔는지는 여기서
확인할 수 없다.** 최소 지원 macOS 를 정하기 전에 반드시 확인해야 한다
(→ 「사용자 결정 항목」 D1).

### 코드 규모

| | 줄 수 | 비고 |
|---|---:|---|
| shell (`lib/`, `bin/`) | 10,992 | `jq` 호출 **247회 / 38파일** |
| python — 생성기·진단 (`lib/`) | 1,827 | 8파일. 파일 호출 12회 + 인라인 `-c` 2회 |
| python — 웹 대시보드 (`templates/`) | 280 | **처음에 빠뜨렸다** (아래 정정) |
| swift (`app/`) | 1,367 | 이미 `platforms: [.macOS(.v14)]` |
| plugin js | 2,157 | Obsidian 안에서만 돎 |

### ⚠️ 정정 (2026-08-23) — 9번째 파일을 빠뜨렸다

처음 실측에서 `lib/` 만 세어 `templates/dashboard/server.py` **280줄**을
놓쳤다. 이건 `devtrail dashboard` 가 띄우는 **로컬 웹 서버**다 — 화이트리스트
명령을 토큰으로 실행하는, 성격이 전혀 다른 서브시스템이다.

python 총량은 1,827 → **2,107줄 / 9파일**이다.

그리고 이건 단순히 "한 파일 더"가 아니다. 나머지 8개는 JSON·텍스트를
만들고 끝나지만, `server.py` 는 **HTTP 서버 + 명령 실행**이다. Swift 로
옮기는 난이도가 다르고, 애초에 DMG 시대에 이 기능이 필요한지가 먼저다
(→ **D5**).

### 이 숫자가 말하는 것

**막는 것은 `jq` 가 아니라 `python3` 하나다.**

- jq 는 이미 OS 에 있다 (최소 버전 확인 조건부)
- bash 3.2 도 항상 있다
- 생성기 python 은 **1,827줄 / 8파일**로 국한돼 있고, 하는 일이 좁다:
  JSON 설정 생성(단축키·Templater·daily-notes·ANM·Smart Connections),
  마크다운 허브 생성, 볼트 진단, 메뉴바용 스냅샷
- 그중 스냅샷은 **이미 Swift 로도 구현돼 있다** (`app/Sources/DevTrailApp/Snapshot.swift`)

10,992줄의 shell 을 건드릴 이유가 없다. 걷어낼 것은 python 한 갈래다.

## 대안

| | A. Python 런타임 번들 | B. Python → Swift 헬퍼 | C. 전체 Swift 이관 |
|---|---|---|---|
| 무엇 | `python-build-standalone` 를 `.app` 안에 넣는다 | `python3` 호출 14곳을 Swift 헬퍼 바이너리로 대체. bash+jq 는 유지 | shell 10,992줄까지 전부 Swift 로 |
| 이관 규모 | 0줄 | **1,827줄** | **12,819줄** |
| 앱 크기 증가 | +40~80MB | +약 1MB (기존 바이너리에 합침) | 비슷 |
| 서명·공증 | 런타임 안 수백 개 `.so` 를 전부 서명해야 함 | 바이너리 1개 | 바이너리 1개 |
| 업데이트 부담 | Python 보안 패치를 우리가 따라가야 함 | 없음 | 없음 |
| 회귀 위험 | 낮음 (코드 그대로) | **중간** — 8파일의 동작을 재현해야 함 | **높음** — 전체 재작성 |
| 기존 CLI 사용자 | 그대로 | 그대로 (헬퍼가 없으면 python3 로 폴백 가능) | **깨진다** |
| 검증 자산 재사용 | 그대로 | 그대로 (`verify-local.sh`·QA 볼트가 그대로 지킨다) | 전부 다시 |

### 결정 — **B** (2026-08-23 승인)

이유:

1. **차단 요인만 정확히 제거한다.** 문제는 python3 하나이고, B 는 그것만 없앤다.
2. **검증 자산이 살아남는다.** `tests/run.sh` 30항목, QA 볼트 하니스 19건,
   `verify-local.sh` 가 그대로 유효하다. C 는 이것을 전부 무효로 만든다.
3. **40~80MB 를 사용자에게 물리지 않는다.** A 는 노트 앱 하나에 Python
   런타임을 얹는다 — 그리고 그 런타임의 보안 패치를 우리가 떠안는다.
4. **되돌릴 수 있다.** 헬퍼가 없거나 실패하면 `python3` 로 폴백할 수 있어,
   기존 Git 설치형 사용자는 아무것도 잃지 않는다.

⚠️ B 의 대가: **1,827줄을 다시 쓴다.** 재현이 정확하지 않으면 생성되는
설정·허브가 조용히 달라진다. 그래서 이관은 **파일 단위 계약 테스트**를
먼저 세우고 진행해야 한다 — 같은 입력에 같은 출력이 나오는지 바이트로
비교한다. 이미 `lib/snapshot.py` ↔ 플러그인 `collect()` 계약 테스트를
같은 방식으로 세운 전례가 있다.

## 7가지 우선 질문에 대한 답

### 1. 비개발자가 git·터미널·Homebrew·Python·jq 없이 설치 가능한가

**조건부 예.** `python3` 의존을 걷어내고, `jq` 가 OS 에 있는 macOS 를 최소로
잡으면 가능하다. `bash` 는 어느 버전이든 있다. 터미널·git 은 DMG 흐름에서
아예 등장하지 않는다.

⚠️ **"어느 macOS 부터 `jq` 가 있는가" 를 확인하지 않았다.** 이 기계
(macOS 26.6)에 있다는 것만 안다. 실기계나 Apple 문서로 확인하기 전까지
최소 버전을 확정하지 않는다 (D1). 확인 결과 지원 대상 중 없는 버전이
있으면 `jq` 단일 바이너리를 번들한다 — 1.5MB, 서명 가능, A 보다 훨씬 가볍다.

### 2. 번들 / Swift 이관 / 자체 포함 중 무엇

**B (Swift 헬퍼)**. 위 비교표 참조.

### 3. 기존 Git 설치형 사용자를 안전하게 발견·유지·전환

발견 신호 (읽기만 한다):

- `~/.devtrail/devtrail.config.json` 존재
- `devtrail` 이 `PATH` 에 있음 + 그 실체가 가리키는 저장소 경로
- 볼트 안 `.obsidian/plugins/devtrail-command-center/manifest.json` 의 버전

세 경로를 **사용자가 고른다**:

| 경로 | 앱이 하는 일 |
|---|---|
| **유지** | 아무것도 바꾸지 않는다. 앱은 기존 설정을 **읽어서** 상태만 보여준다 |
| **전환** | 설정을 그대로 두고 앱이 관리 주체가 된다. 기존 `devtrail` 명령은 계속 동작 |
| **취소** | 앱이 종료된다. 파일 한 개도 만들지 않는다 |

⚠️ **자동 전환을 하지 않는다.** 버전이 다르거나 판단이 서지 않으면 앱은
아무것도 하지 않고 무엇이 다른지만 보여준다.

### 4. 앱·플러그인·템플릿·설정 스키마의 단일 릴리즈 버전 계약

`VERSION` 파일 하나가 정본이다 (현재 `0.5.0`). 이미 태그 ↔ `VERSION` 일치를
CI 가 검사한다.

새로 필요한 것은 **릴리즈 매니페스트**다:

```json
{
  "schema": 1,
  "version": "0.6.0",
  "app": { "bundle_version": "0.6.0", "min_macos": "<D1 에서 확정>" },
  "plugin": { "id": "devtrail-command-center", "version": "0.14.0" },
  "config_schema": 3,
  "artifacts": [{ "name": "DevTrail-0.6.0.dmg", "sha256": "…", "size": 0 }]
}
```

⚠️ **네 가지가 따로 움직이면 안 된다.** 앱이 config schema 3 을 쓰는데
템플릿이 4 를 가정하면 사용자 볼트가 조용히 어긋난다. 매니페스트를
게이트가 소비하게 만든다 — 문서에 적기만 하면 곧 거짓말이 된다.

### 5. MVP DMG 와 정식 DMG 의 차이

| | MVP | 정식 |
|---|---|---|
| 서명 | ad-hoc (`codesign -s -`) | **Developer ID Application** |
| 공증 | 없음 | `notarytool` + `stapler` |
| 여는 법 | 우클릭 → 열기 (Gatekeeper 경고) | **더블클릭** |
| 대상 | 내부·얼리 테스터 | 일반 사용자 |
| Apple 계정 | **불필요** | 필요 ($99/년) |
| 빌드 | 로컬 | 로컬 (Actions 예산 정책 유지) |

MVP 는 "설치 흐름이 실제로 되는가"를 확인하는 것이 목적이다. Gatekeeper
경고를 넘기는 법을 비개발자에게 설명해야 하므로 **일반 배포에는 쓸 수 없다.**

### 6. Apple Developer 계정·인증서가 필요한 정확한 시점과 비용

- **필요 시점**: 정식 DMG 를 **일반 사용자에게 배포하기 직전**. 그전에는 불필요
- **비용**: Apple Developer Program **US$99 / 년** (개인)
- **필요한 것**: Developer ID Application 인증서 (앱 서명) — DMG 자체를
  서명하는 데도 같은 인증서를 쓴다. `notarytool` 은 계정 자격 증명이 필요
- ⚠️ 갱신을 놓치면 **새 서명을 만들 수 없다.** 이미 공증·스테이플된 배포물은
  계속 열리지만 새 릴리즈를 낼 수 없다

### 7. 수동 업데이트부터 시작하고 자동 업데이트를 미루는 이유와 경계

**이유** — 자동 업데이트는 세 가지를 동시에 요구한다:

1. 서명 검증 (가짜 업데이트를 받지 않기)
2. 실패 시 롤백 (부분 교체된 상태로 남지 않기)
3. **교체 시점 통제**

3번이 핵심이다. **Obsidian 이 실행 중일 때 플러그인 파일을 바꾸면 안 된다.**
Obsidian 은 시작할 때 플러그인을 읽고, `require.cache` 가 `undefined` 라
[ADR 0004](./0004-plugin-file-split.md) 에서 재적재 여부를 확인하지 못했다.
자동 업데이트는 사용자가 편집 중인 순간에 파일을 갈아치울 수 있다.

**경계** — 나중에 Sparkle 을 도입할 수 있게 남겨 둘 것:

- 릴리즈 매니페스트 (위 4번) 가 appcast 로 확장 가능한 모양일 것
- 버전 비교는 SemVer 로, 다운그레이드 금지는 **이미 구현돼 있다**
- 플러그인 교체는 **Obsidian 종료 상태에서만** — 이 계약을 앱 코드에 박아 둘 것
- Sparkle 은 EdDSA 서명 키를 요구한다. 그 키를 어디에 두는지는 도입 시점에 결정
