# Command Center 사용법

`⌘⇧Y` 로 엽니다. 이 화면은 **읽기 모델**입니다 — 노트를 보여주고 기록 명령으로
이어줄 뿐, 노트를 직접 고치지 않습니다.

## 역할 분리 — 같은 일을 두 곳에 적지 않는다

| 무엇 | 어디 |
|---|---|
| 아직 분류하지 않은 포착물 | **Inbox** |
| 프로젝트 수준의 진행 상태 | **프로젝트 보드** |
| 오늘 실제로 할 일 | **오늘 개발일지의 체크박스** |
| 판단 · 문제 · 결과 | 개발메모 · 트러블슈팅 · 워크로그 |
| 전체 검색 | Omnisearch (없으면 Obsidian 기본 검색) |

⚠️ **개발일지 체크박스를 보드 카드로 만들지 않습니다.** 같은 일을 두 곳에 적으면
어느 쪽도 믿을 수 없게 됩니다. 보드는 프로젝트가 어디쯤 왔는지, 개발일지는 오늘
무엇을 하는지 — 묻는 질문이 다릅니다.

## 흐름

```
빠른 기록  →  Inbox
                ↓  매일/주간 정리
          프로젝트 생성 또는 연결
                ↓
     보드에서 stage · next_action 확인
                ↓
       오늘 개발일지 체크박스로 실행
                ↓
   개발메모 · 트러블슈팅 · 워크로그 기록
                ↓
          프로젝트 완료 또는 보관
```

## 프로젝트 보드

카드 하나가 프로젝트 노트 하나입니다. 눌러서 (또는 `Enter`·`Space`) 노트를 엽니다.

### stage — 컬럼을 정하는 값

프로젝트 노트 앞머리에 씁니다:

```yaml
---
type: project-home
status: active
stage: in-progress
next_action: 로그인 API 에러 응답 정리
---
```

| 컬럼 | 색 | 쓸 수 있는 값 |
|---|---|---|
| 계획 중 | 회색 | `planning` · `planned` · `plan` |
| 진행 중 | 보라 | `in-progress` · `in_progress` · `active` · `doing` |
| 막힘 | 빨강 | `blocked` |
| 완료 · 보관 | 초록 | `done` · `completed` · `complete` · `archived` |

대소문자와 앞뒤 공백은 견딥니다.

⚠️ **모르는 값은 아무 컬럼에도 넣지 않습니다.** `stage` 가 비었거나 위 목록에 없는
값이면 보드 위 **단계 미지정** 영역에 모입니다. 지정하지 않은 상태를 '계획 중'
이라고 보여주면 화면이 사실이 아닌 것을 말하게 됩니다.

`status` 는 프로젝트가 살아 있는지를 판별하는 값이고, 컬럼은 `stage` 가 정합니다 —
두 값은 다른 질문에 답합니다.

### next_action — 카드에서 가장 먼저 읽히는 줄

**다음에 손댈 한 가지**를 한 줄로 씁니다. 목록이 아닙니다.

```yaml
next_action: 결제 웹훅 재시도 정책 정하기      # 좋음 — 다음 행동 하나
next_action: 개발                              # 나쁨 — 무엇을 할지 모름
next_action: API 정리, 테스트, 배포            # 나쁨 — 세 가지
```

비어 있으면 카드가 **"다음 행동 없음"** 이라고 말합니다. 채우라는 신호입니다.

### 색

색은 세 번째 신호입니다. 모든 컬럼에 **아이콘과 글자**가 함께 있습니다 —
색만으로 상태를 말하면 라이트 테마와 색각에서 무너집니다.

## 검색

DevTrail 은 **검색기를 만들지 않습니다.** 화면 위 검색 버튼은 통로입니다:

1. Omnisearch 가 있으면 그 명령을 부릅니다
2. 없으면 Obsidian 기본 검색으로 떨어집니다
3. 둘 다 없으면 버튼이 눌리지 않고 무엇을 설치하면 되는지 말합니다

## 빠른 실행

검색 바로 아래 — 찾기 다음은 남기기입니다. 전부 **Templater 명령**을 부릅니다.

명령이 없으면 버튼이 **눌리지 않습니다.** 조용히 다른 노트를 만드는 대신
`devtrail obsidian` 실행과 Obsidian 재시작을 안내합니다.

## 업데이트

```
devtrail command-center status     지금 상태
devtrail doctor                    설치·버전·업데이트 여부
devtrail command-center update     무엇이 바뀌는지만 (파일 안 바꿈)
devtrail command-center update --apply
devtrail undo <작업> --apply       되돌리기
```

⚠️ **Obsidian 을 켤 때 자동으로 검사하지 않습니다.** 위 명령을 실행할 때만
비교합니다. 화면이 스스로 무언가를 받아오는 일도 없습니다.

⚠️ **적용 뒤에는 Obsidian 을 완전히 종료(`⌘Q`)했다가 다시 열어야 합니다.**
Obsidian 은 시작할 때만 플러그인을 읽습니다 — 실행 중에 파일을 바꿔도 화면은
옛 코드 그대로입니다. 화면이 소스와 달라 보이면 **십중팔구 이것**입니다.

설치본과 저장소 버전이 같은지 확인하려면:

```
devtrail command-center status --json | jq '{installed_version, available_version, update_state}'
```

`update_state` 는 셋 중 하나입니다:

| | |
|---|---|
| `up_to_date` | 같음 |
| `update_available` | 저장소가 더 새로움 |
| `installed_newer` | **설치본이 더 새로움** — 낮추지 않습니다 |

## Obsidian 없이 링크 받아두기

```
devtrail capture youtube --url "https://youtu.be/…"          # 무엇이 생길지만
devtrail capture youtube --url "https://youtu.be/…" --apply  # 실제로 만든다
devtrail undo <작업> --apply                                  # 되돌리기
```

Obsidian 이 꺼져 있어도 됩니다. 다음에 열면 노트가 보입니다.

**받는 주소:** `watch?v=…` · `youtu.be/…` · `shorts/…` (파라미터가 붙어도 됩니다)
채널·재생목록 주소는 받지 않습니다 — 무엇을 저장할지 정할 수 없기 때문입니다.

**같은 영상을 다시 넣으면** 새 노트를 만들지 않고 기존 노트가 어디 있는지
알려줍니다. 영상 id 로 판별하므로 `youtu.be` 든 `watch?v=` 든 같은 것으로 봅니다.

⚠️ **요약과 적용점은 비어 있습니다.** 캡처는 받아두는 일이고, 자막을 읽고
`tl_dr_oneline` 과 `key_for_me` 를 채우는 것은 유튜브 스킬이 합니다.
빈 칸은 "아직 안 했다" 는 사실입니다 — 그럴듯한 문장으로 채우지 않습니다.
노트의 `status` 가 `inbox` 인 이유가 이것입니다.

⚠️ **네트워크는 저장할 때만 씁니다.** URL 을 넣는 것만으로 요청하지 않고,
제목·채널만 가져옵니다. 실패해도 URL 로 저장합니다 — 링크를 잃는 것보다 낫습니다.
자막 전문은 노트에 옮기지 않습니다.

## 이번 버전에 없는 것

| | 이유 |
|---|---|
| **카드 끌어 옮기기** | 노트를 고치는 순간 플러그인이 두 번째 쓰기 출처가 됩니다 |
| **작업(task) 단위 칸반** | 새 스키마가 필요합니다 — 별도 ADR |
| **개발 활동 캘린더** | 기록이 쌓인 뒤에 판단합니다 |

상태를 바꾸려면 노트의 `stage` 를 직접 고칩니다. 저장하면 보드가 따라옵니다.
